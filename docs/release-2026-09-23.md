# Backend release repair — 2026-09-23

## Scope and policy

The initial release run had 925 passing checks and 41 failures. Failures included
both real authorization regressions and fixtures/assertions left behind by recent
price-range, forex, scoring-policy and allocation changes.

The user explicitly confirmed that **discretionary manual Buy bypasses SmartMoney
policy gates**. This release preserves that behavior, including bypassing quote
verification. Broker rejection, valid order terms, confirmed-amount limits, stable
order identity and duplicate-order handling are not removed. AI-sized buttons and
automatic orders remain separate from discretionary manual Buy. No real orders
are submitted for release testing.

Existing stock F70, crypto F65, scoring weights, contribution calculations and
memory settings are unchanged. Baseline fixtures now describe the already
committed F70/uncapped-Discovery-in-F policy rather than the older F78 policy.

## Repairs

- Automatic stock approval cannot bypass explicit rejection, required approval
  flags, central authorization or decision expiration merely because F is high.
- Automatic crypto eligibility checks current evidence, central authorization,
  expiry, required approval flags and risk blockers. Cached F cannot override
  weaker current evidence; quote recovery alone cannot reauthorize a purchase.
- Allocation creation checks central eligibility before issuing approval flags;
  rejection clears old approved amounts. Execution consumes an allocation rather
  than issuing a new one. Adaptive sizing cannot exceed the approved ceiling.
- An explicitly locked real-cash account cannot receive automatic allocation
  approval for either asset class. Tests cover both paths.
- The actual crypto server wrapper now routes explicit discretionary manual
  requests directly to the order service, without automatic mode, unlock or
  live-safety policy gates. A test extracts and executes that wrapper with mocked
  order submission, proving manual bypass and automatic rejection separately.
- Crypto approved counts require explicit approval and canonical F65 in addition
  to execution eligibility.
- Bulk stock/crypto quote revalidation yields to I/O every four candidates.
  Repeated full-population health timeouts reproduced before this change; the
  same 60-stock/73-crypto test then passed at 182 MB peak RSS with a maximum
  observed HTTP response time of 1,991 ms. No timeout limit was relaxed.
- Config endpoints reject enabling automation during daily safety locks and allow
  an explicit user OFF without requiring emergency stop first.
- Pending stock price-range filtering is included. Live movers and signal routes
  now use the saved range consistently; range changes invalidate mover caches.
  Price-cap startup migration remains in its separate committed module.
- Test harnesses now load the actual forex currency and allocation dependencies.
  Scoring tests using $100 fixtures explicitly configure a compatible price range.
  Assertions that authorized rejected/expired automatic decisions were corrected;
  manual-policy assertions reflect the user's explicit exception above.
